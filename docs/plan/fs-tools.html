Key code

Two snippets where small mistakes silently break the sandbox. Everything else is mechanical.

reigner/tools/fs/store.py — trust boundary
def resolve(self, rel: str) -> Path:
    """Resolve a root-relative path. Reject abs, ``..`` escape, and out-of-root symlinks."""
    if not isinstance(rel, str) or not rel:
        raise ValueError("path must be a non-empty string")
    if rel.startswith(("/", "\\")):
        raise ValueError(f"path must be relative, got {rel!r}")
    candidate = (self.root / rel).resolve()    # follows symlinks
    try:
        candidate.relative_to(self.root)        # post-resolve = symlink-safe
    except ValueError as exc:
        raise ValueError(f"path {rel!r} escapes fs root") from exc
    return candidate
reigner/tools/fs/store.py — gated tool assembly
def tools(self) -> list[RunnableToolAdapter]:
    funcs = [
        build_fs_read(self),
        build_fs_grep(self),
        build_fs_glob(self),
        build_fs_ls(self),
    ]
    if self.write_enabled:
        funcs.append(build_fs_write(self))      # omission, not runtime denial
    return [to_runnable(f) for f in funcs]
reigner/tools/fs/store.py — ignore predicate
_IGNORED_DIRS = {".git", "node_modules", "__pycache__", ".venv", ".mypy_cache", ".ruff_cache"}

def _is_ignored(self, path: Path, *, include_hidden: bool) -> bool:
    for part in path.relative_to(self.root).parts:
        if part in _IGNORED_DIRS:
            return True
        if not include_hidden and part.startswith("."):
            return True
    return False

Future scope

Things deliberately deferred and the assumptions baked into this plan.

Regex in fs_grep?

Literal-only for v0 — matches grep_artifact's decision and avoids ReDoS plumbing. Code-search users can still find symbols. Revisit if eval signal shows the model is paraphrasing to dodge literal matching.

Decide with · recipe owners · after code_navigator (T-33) has eval data

.gitignore parsing

Skipped: ships hardcoded ignores for .git / node_modules / __pycache__ / .venv / .mypy_cache / .ruff_cache + dotfile filter. Adding pathspec later is straightforward; not adding it now keeps the dep surface flat and behavior predictable in repos without a .gitignore.

Decide with · code_navigator usage data

Edit-style fs_write

v0 ships whole-file overwrite only. An old_string / new_string edit semantic is much more code and more failure modes; the "raw filesystem" framing argues against it. Recipes that need partial edits should compose fs_read + fs_write until there's signal otherwise.

Decide with · code_navigator owners

Tunable text-extension allowlist

Assumption: ship a default code+text set on the class (.py .js .ts .tsx .jsx .md .txt .json .yaml .yml .toml .rs .go .java .c .h .hpp .cpp .css .html .sh and similar). Override via constructor kwarg. If review prefers the artifact-style minimal default ({.csv .json .jsonl .md .txt .tsv .yaml .yml}), say so and I'll narrow it.

Decide with · reviewer during this PR

Bounds via reigner.yaml

Bounds live on the FsTools constructor for now. Wiring them through project config is a follow-up that should happen once the config loader stabilizes — premature otherwise.

Profile placement

Assumption: FS tools are not added to any built-in profile (full, read_only, eval) by default — they're opt-in per recipe. code_navigator (T-33) registers them explicitly. Flag in review if FS reads should be auto-included in read_only.
