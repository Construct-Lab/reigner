reigner/tools/search/bm25.py — the scoring loop (the part most likely to drift from textbook BM25)
def _score(self, query_tokens: list[str], doc_id: str) -> float:
    # Classic BM25: sum over query terms of IDF * tf_norm
    k1, b = 1.5, 0.75
    dl = self._doc_len[doc_id]
    avgdl = self._avgdl
    score = 0.0
    for term in query_tokens:
        df = self._df.get(term, 0)
        if df == 0:
            continue
        idf = math.log(1 + (self._N - df + 0.5) / (df + 0.5))
        tf = self._tf[doc_id].get(term, 0)
        score += idf * (tf * (k1 + 1)) / (tf + k1 * (1 - b + b * dl / avgdl))
    return score
reigner/tools/search/bm25.py — tools() returns @tool-decorated closures so each call captures `self`
def tools(self) -> list[ToolCallable]:
    index = self  # closure capture

    @tool(readonly=True, cache=True)
    async def bm25_search(
        query: str,
        filters: dict[str, str | list[str]] | None = None,
        top_k: int = 5,
    ) -> dict:
        """BM25 search over the compiled corpus."""
        if not query.strip():
            raise ValueError("query must be non-empty")
        return index._search_text(query, filters, min(top_k, 20))

    @tool(readonly=True, cache=True)
    async def filtered_search(
        filters: dict[str, str | list[str]],
        top_k: int = 5,
    ) -> dict:
        """Return entries matching filters, sorted by id."""
        return index._search_filtered(filters, min(top_k, 20))

    @tool(readonly=True, cache=True)
    async def section_search(
        query: str, section_name: str, top_k: int = 5,
    ) -> dict:
        """BM25 scored against one named section only."""
        if not query.strip():
            raise ValueError("query must be non-empty")
        return index._search_section(query, section_name, min(top_k, 20))

    return [bm25_search, filtered_search, section_search]

Future scope

Deliberate omissions, assumptions to revisit, and the natural follow-ons.

Vector / SQL backends

SPEC §3 and §19 explicitly defer these. The SearchIndex protocol is shaped to accept them later without renegotiation — a vector backend ships its own tool names via tools(). No code in this PR; only the contract.

Decide with · contributors · post-v0

Citation/provenance fields on hits

T-12 will turn tool results into CitationEvent. This PR returns id, source, and snippet — enough for T-12 to construct citations without coupling to T-12's not-yet-final shape. If T-12 lands and needs more (e.g. byte offsets), revisit.

Decide with · T-12 author · when T-12 starts

Snippet quality

v1 ships a ~240-char window around the earliest matched token, word-boundary snapped. No highlighting markers, no multi-window concat. Acceptable for v0 because the model can always read the full artifact via read_artifact_file (T-09). Revisit if eval cases show citation-locating regressions.

Decide with · eval results from T-29

Index reload at runtime

Eager load in __init__; index is immutable for the life of the Bm25Index object. Matches SPEC's "ingestion is a one-time compilation step." If users want hot-reload, they reconstruct the harness. A reload() method is cheap to add later if needed.

Decide with · user feedback · post-v0

Filter operators (range, contains, regex)

v1 supports exact match + list-OR only. Operators (year__gte, entity_id__in) are out of scope — they expand the parsing surface and the docs without an attested use case. Easy to add to filters.py when one shows up.

Decide with · first recipe needing it

Assumption: identifiers values are strings

The writer stores identifiers: dict[str, str] and the filter language compares strings. If a future recipe sets numeric or date identifiers, we'll need either string coercion in the filter matcher or a typed filter language. Flagged here so reviewers can push back.

Assumption · revisit if eval recipes break

Performance ceiling

Pure-Python BM25, full inverted index in memory, no compression. Fine for the SEC 10-K reference corpus (≤ a few thousand entries, ≤ a few hundred MB text). For larger corpora, the natural next step is a contributed Tantivy / Lucene backend behind SearchIndex — not a rewrite of Bm25Index.
