class UserQueryEvent(Event):

# Session.run_stream — before driving the loop:

reigner/sessions/replay.py — regroup one round's events into the ModelActions the loop produced
def _round_to_actions(events): # events of ONE round (turn resets to 0 each round)
    results, by_turn = {}, defaultdict(list)
    for ev in events:
        by_turn[ev.turn].append(ev)
    actions = []
    for turn in sorted(by_turn):
        calls = [ToolCall(id=e.call_id, name=e.name, args=e.args)
                 for e in by_turn[turn] if isinstance(e, ToolCallEvent)]
        for e in by_turn[turn]:
            if isinstance(e, ToolResultEvent): results[e.call_id] = e.result
        final = next((e for e in by_turn[turn] if isinstance(e, FinalAnswerEvent)), None)
        if final: actions.append(ModelAction(is_final_answer=True, text=final.text))
        elif calls: actions.append(ModelAction(is_final_answer=False, tool_calls=calls))
    return actions, results  # results feed the stub tools, keyed by call_id
reigner/harness/agent.py — Session.replay
async def replay(self, at_turn: int) -> "Session":
    """Fork at round N, re-issue round N's recorded query live against this
    Harness's current model & ROLE (SPEC §11.2). Original is untouched."""
    bounds = round_boundaries(self._events)        # index per UserQueryEvent
    query = self._events[bounds[at_turn - 1]].query
    child = self.fork(at_turn=at_turn)             # history = rounds 1..N-1
    async for _ in child.run_stream(query): pass  # runs live, persists to child
    return child
06

Future scope

What's deliberately deferred, plus the assumptions baked into this plan for you to overrule on review.

Interleaved assistant text is lost on reconstruction

When the model emits prose alongside tool calls, the loop stores it in history but no event carries it (only FinalAnswerEvent has text). So reconstruction can't recover it — tolerable, since queries, tool calls, and results all survive, and re-run's headline case (model swap) dwarfs lost narration. The real fix is to log that text; it's an event-protocol change, out of scope here.

Decide with · maintainer · when a narration-heavy model becomes the default

Schema migration for v1 sessions

Bumping to SCHEMA_VERSION=2 means existing v1 JSONL has no UserQueryEvent. Assumption: v1 sessions stay inspectable (events(), tree()) but reconstruct/replay raise a clear "no recorded query" error rather than silently guessing. No data rewrite.

Decide with · reviewer · this PR (flag if hard-fail is preferred)

Snapshot duplication vs delta+lineage

Copying the parent prefix into each child makes branches self-contained but duplicates bytes; deep fork trees over long sessions grow. We chose snapshot for v0 simplicity and crash-safety. Revisit a delta+lineage store if session sizes make duplication costly.

Decide with · maintainer · post-v1, if storage shows up as a problem

Explicit model / role overrides on replay

Today replay uses whatever Harness it's attached to (SPEC §11.2: "against current model & ROLE"); to A/B a model you load the session into a second Harness. The SPEC CLI hints at --with-role, so ergonomic replay(model=, with_role=) params are a natural follow-up.
