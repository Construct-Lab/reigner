02

Data flow

One case, left to right: load → run the harness (solid sync drain of the event stream) → assemble a CaseRun → fan out to both evaluation tiers → aggregate → render. Terracotta boxes are new.

Solid = request/response & synchronous drain. Dashed = async / fire-and-forget (none here — the runner awaits each case fully before checking). Terracotta border = new module. Cases run sequentially; a fresh eval-profile session per case means zero cross-case state leak.

05

Key code

The two spots most likely to be done wrong: the registry seam T-29 inherits, and the per-case drain that must never let one bad case abort the suite.

reigner/eval/checks.py — the seam T-29 plugs into
from typing import Literal, Protocol

@dataclass
class CaseRun:
    final: FinalAnswerEvent | None   # None = clarified / errored / no answer
    events: list[Event]
    citations: list[Citation]
    elapsed: float
    usage: dict

@dataclass
class CheckResult:
    name: str
    status: Literal["pass", "fail", "na"]
    detail: str = ""

class Check(Protocol):
    async def __call__(self, case: EvalCase, run: CaseRun) -> CheckResult: ...

_REGISTRY: dict[str, Check] = {}

def check(name: str):                 # T-29 decorates its 5 fns with this
    def register(fn: Check) -> Check:
        if name in _REGISTRY:
            raise ValueError(f"duplicate check {name!r}")
        _REGISTRY[name] = fn
        return fn
    return register
reigner/eval/runner.py — per-case drain, suite never aborts
async def _run_case(self, harness, case, checks) -> CaseResult:
    session = harness.session(profile="eval")   # fresh, isolated
    final, events = None, []
    t0 = time.perf_counter()
    try:
        async for ev in session.run_stream(case.query):
            events.append(ev)
            if isinstance(ev, FinalAnswerEvent):
                final = ev
    except Exception as exc:                  # a bad case can't sink the suite
        events.append(_error_event(exc))
    run = CaseRun(final, events, session.citations(),
                  time.perf_counter() - t0, _usage(final))

    results = self._intrinsic(case, run)            # always: phrases + clarification
    for name in checks:                          # named tier, registry lookup
        results.append(await _REGISTRY[name](case, run))
    passed = all(r.status != "fail" for r in results)  # na/pass both OK
    return CaseResult(case, run, results, passed)

Future scope & assumptions

What this task deliberately leaves to adjacent issues, plus assumptions made where the conversation didn't pin every nail.

The five concrete checks — T-29

faithfulness, repeated_calls, entity_resolution, coverage, latency_cost are out of scope here. This task only proves the seam works (one fake check in tests). T-29 decorates real implementations with @check — no runner edits required when it lands.

Decide with · T-29 owner · next

Sequential, not concurrent

Cases run one at a time. Determinism and predictable token cost are the point of the eval profile, and cases are independent so concurrency is a trivial later add (an asyncio.gather with a semaphore). Not worth the nondeterministic ordering and cost-spike risk for v0.

Revisit if · eval suites grow large enough to be slow

Assumption · expected_citations matching lives in T-29

EvalCase.expected_citations is stored as list[str] and passed through untouched. The actual matching against registered citations (via the existing citation_id() / canonicalize_locator() helpers) belongs to the coverage/faithfulness checks. Note the SPEC's illustrative form source#research_and_development differs from what citation_id emits (source#field=research_and_development); T-29 will need to settle that — out of scope here, flagged so it isn't lost.

Decide with · T-29 owner · when faithfulness lands

Assumption · expected_clarification is tri-state

Modeled as bool | None = None so None means "don't assert." This avoids forcing a misleading "should not clarify" row onto every case that simply omitted the field. The cases.yaml scaffold shows false, which still works — only omission is treated as no-op.
