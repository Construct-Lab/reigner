Implementation plan · Reigner

Auto-register pseudo-tools and register_citation

Prompt

Issue #64 — the four pseudo-tools (save_note, request_clarification, escalate_to_oracle, stop) and register_citation are intercepted by the loop but never registered. The model can't see them in its tool schema list, so SPEC §6.4 "always available" and SPEC §1 principle 4 (citations first-class) are silently broken. Wire them into Harness.from_config so the registry exposes them by default.

Key code

The whole change is a few lines in one function. The thing easiest to get wrong is the oracle gate and the registration order — builtins must come first so user-tool collisions raise loudly instead of silently shadowing SPEC §6.4 verbs.

reigner/harness/agent.py — Harness.from_config
from reigner.tools.provenance import register_citation
from reigner.tools.pseudo import (
    escalate_to_oracle,
    request_clarification,
    save_note,
    stop,
)

...

builtin_tools: list[RunnableTool] = [
    save_note,
    request_clarification,
    stop,
    register_citation,
]
if oracle_adapter is not None:
    builtin_tools.append(escalate_to_oracle)

registry = ToolRegistry()
for t in (*builtin_tools, *artifact_tools, *search_tools,
              *custom_tools, *(tools or [])):
    registry.register(t)  # type: ignore[arg-type]
tests/harness/test_agent_builtin_tools.py — collision case
def test_user_tool_colliding_with_builtin_raises(tmp_path):
    # Builtins register first; a user-supplied save_note must error.
    cfg = _write_config(tmp_path, custom=["tests.fixtures.fake_save_note"])
    with pytest.raises(ToolRegistrationError):
        Harness.from_config(cfg)
06

Future scope

What this PR deliberately does not touch.

Per-name disable knob (SPEC §6.4 "unless explicitly disabled")

SPEC permits opting builtins out by name. No current consumer needs this — adding a tools.builtins_disabled: list[str] field now would mean config surface, validation, and a deprecation path with no driver. Defer until a real use case lands; until then, the literal SPEC wording is honored by the fact that nothing is disabled.

Decide with · @ananthanandanan · when a consumer asks

User overrides for builtin tool names

This plan picks "builtins win, user collisions raise loudly." The alternative — letting users redefine save_note — requires loosening ToolRegistry's duplicate-name guard and is a bigger change. Not in scope for the bug fix.

Decide with · @ananthanandanan · later
