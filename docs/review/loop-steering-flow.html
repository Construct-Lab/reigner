Loop & steering — a steered query, frame by frame

Watch one REPL query travel through the harness, get steered mid-flight, and resolve. The animation loops every 32 seconds; pause and scrub to study any phase. The narration below the diagram highlights the currently-active step.

Scenario: the user asks "Summarize §2 and §3 of the doc." Iteration 1 fires two read_section tool calls in parallel (G11). While the model is still working, the user changes their mind and hits Enter mid-run with "actually just §3, skip §2". That message lands on state.pending_steering. Iteration 2 drains it before the next model call — the model now sees the corrected instruction in its prompt history and responds accordingly.

narration · the moving parts

  1. User submits query. In the REPL, the user types Summarize §2 and §3 of the doc. and presses Enter. With running idle, the Enter binding exits the prompt with the text as result.
  2. Session.run_stream(query). The CLI's _drive_run coroutine starts iterating the harness's async generator. The query is appended to state.history as a user turn.
  3. Iteration 1, step ①: refresh_context. Per-turn dynamic context (iters_remaining, now, etc.) is recomputed (G6/G7).
  4. Step ②: has_pending_steering? The loop peeks at state.pending_steering. It's empty on the first iteration — nothing to drain, no SteeringAcceptedEvent.
  5. Steps ③ & ④: compaction + nudges. progressive(state) checks if history is over 80/90/95% of the token budget (G5/G10); iteration_nudge(state) would inject a strategic nudge every N iterations (G3). Both are no-ops here.
  6. Step ⑤: state.build_prompt(). The stable/dynamic boundary is assembled (G1) — role text + tool schemas (cacheable) + history + per-turn dynamic context.
  7. Step ⑥: adapter.call(prompt). The blue token rides the prompt out to the model adapter. The model decides it needs to read both sections and returns a ModelAction with two tool_calls.
  8. Step ⑦: dispatch tool_calls. Both calls are readonly=True, so should_parallelize green-lights a parallel batch (G11). execute_batch fires them concurrently; each result passes through ToolResultCache (G9, miss this turn) and truncate_for_tool (G2).
  9. Step ⑧: yield Events. Two ToolCallEvents emit in original order, then two ToolResultEvents in the same order. Watch the green chips appear in the event stream below.
  10. ★ User steers mid-run. Before iteration 2's adapter.call returns, the user hits Enter with actually just §3, skip §2. The REPL's _on_enter binding sees running.is_set() and instead of submitting, fires asyncio.create_task(session.steer(text, "interrupt")).
  11. Session.steer → AgentState.enqueue_steering. The 3-line wrapper appends (message, "interrupt") to state.pending_steering. The orange item is now visible in the inbox. The running iteration is not preempted; the keystroke just dropped a note in the inbox.
  12. Iteration 2 begins. The previous iteration completed its tool batch and the while ticks. refresh_context runs again, then the loop reaches step ②.
  13. ★ DRAIN. has_pending_steering → True. for (message, mode) in state.consume_steering(): — the loop pulls the item, appends a new Turn(role="user", content=message) to state.history, and yields SteeringAcceptedEvent. Watch the orange token fall from the inbox into history; watch the inbox empty; watch the orange chip appear in the event stream.
  14. Step ⑤ (iter 2): build_prompt. History now ends with the steer message. The next prompt the model sees has the corrected instruction as its most recent user turn.
  15. Step ⑥ (iter 2): adapter.call. The model receives a prompt that ends with "actually just §3, skip §2" and responds with a final answer about only §3.
  16. Step ⑧: yield FinalAnswerEvent. Loop sets state.done = True, emits the event, returns. The async generator is exhausted.
  17. REPL renders the green panel. _render_event catches the FinalAnswerEvent and prints it inside rich.Panel(border_style="green"). Prompt comes back live for the next query.
  18. What "drained" means. The queue is consulted exactly once per iteration, at one specific site near the top of while not state.done. Whatever is in pending_steering at that moment is removed and folded into history. After the drain, the list is empty again. The model never sees the queue directly — it only ever sees turns in history.
